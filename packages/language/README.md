# The mandatory language package

As a good entry point to our documentation, please use to this [guide](https://langium.org/docs/learn/workflow/write_grammar/).

## What's in the folder?

- [package.json](./package.json) - The manifest file of your language package.
- [tsconfig.src.json](./tsconfig.src.json) - The packages specific TypeScript compiler configuration extending the [base config](../../tsconfig.json)
- [tsconfig.json](./tsconfig.json) - TypeScript compiler configuration options required for proper functionality of VSCode.
- [src/alloy-lsp.langium](src/alloy-lsp.langium) -  The grammar definition of your language
- [src/alloy-lsp-module.ts](src/alloy-lsp-module.ts) - The dependency injection module of your language implementation. Use this to register overridden and added services.
- [src/alloy-lsp-validator.ts](src/alloy-lsp-validator.ts) - An example validator. You should change it to reflect the semantics of your language.
- [src/generated/ast.ts](src/generated/ast.ts) - AST generated by `langium generate`.
- [src/generated/grammar.ts](src/generated/grammar.ts) - Grammar generated by `langium generate`.
- [src/generated/module.ts](src/generated/module.ts) - Module generated by `langium generate`.
- [syntaxes/alloy-lsp.tmLanguage.json](syntaxes/alloy-lsp.tmLanguage.json) - Textmate based syntax highlighting instructions.
- [src/index.ts](src/index.ts) Defines what is exported to other packages.

If you selected the test option as well, then the following files will be present in addition:

- [tsconfig.test.json](./tsconfig.test.json) - The package specific TypeScript compiler configuration for the unit tests extending the [tsconfig.src.json](./tsconfig.src.json)
- [test/linking.test.ts](test/linking.test.ts) - Unit tests checking linking.
- [test/parsing.test.ts](test/parsing.test.ts) - Unit tests regarding parsing.
- [test/validating.test.ts](test/validating.test.ts) - Unit tests regarding validation.

## Tests

- `npm test` runs the unit tests: parsing, linking, typing, LSP features and the Analyzer integration (whose jar-gated cases skip without a jar).
- `npm run test:oracle` checks the test expectations against the real Alloy Analyzer: every syntax case, typing case and example in [`examples/`](../../examples) goes through `alloy.jar commands`, and its verdict must match ours. It needs Java and `ALLOY_JAR` (or the jar at `~/code/tools/alloy/alloy-6.2.0.jar`); the shared cases live in [test/cases](test/cases).
- `npm run test:corpus` checks that the 86 models of the AlloyTools repository, all accepted by the Analyzer, give no diagnostics of ours. Fetch them once with `npm run corpus:fetch` (it needs git and the network); they land in the git-ignored `test/corpus/models`, and the check skips without them.
